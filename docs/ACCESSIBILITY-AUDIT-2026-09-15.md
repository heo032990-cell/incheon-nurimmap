# 누림지도 화면낭독기 이용 관점 점검

- 점검일: 2026-09-15
- 운영 대상: https://incheon-nurimmap.netlify.app/
- 참고 소스: GitHub codex/survey-integration, 0cf61e63b1bc12799c07d8272bec31c1b8834d8c. 운영 배포와 이 커밋이 완전히 같다는 검증은 하지 않았다.
- 방법: 운영 브라우저 접근성 트리, DOM의 접근성 속성, 키보드 Tab/Enter/Escape 및 실제 검색·신청창 조작, GitHub 소스 검토.
- 한계: NVDA·센스리더·VoiceOver의 실제 음성 출력은 실행하여 확인하지 않았다. 접근성 인증이나 전체 WCAG 적합성 판정이 아니다. 실제 신청 제출·개인정보 동의·파일 업로드·관리자 변경은 하지 않았다. 합성 점검값으로 신청 정보에서 동의 화면까지 이동 후 닫았다.

## 확인된 정상 동작

- 첫 Tab → Enter로 본문 바로가기를 실행하면 mainContent에 초점이 이동한다.
- 검색어, 연령, 복지관, 장애유형, 참여대상, 모집상태, 정렬 입력에 이름이 있다.
- 프로그램 제목은 heading, 신청 버튼은 프로그램명을 포함한 이름으로 전달된다.
- 생년월일의 연도·월·일 선택기에 각각 이름이 있다.
- 복지관을 인천시각장애인복지관으로 선택하면 결과 없음과 검색 결과 0개가 일치한다.
- 신청 버튼 Enter로 제목이 있는 dialog가 열리고 닫기 버튼에 초점이 간다.
- 빈 신청 정보에서 다음을 누르면 이름 입력에 초점이 가고 aria-invalid=true가 붙는다.
- 신청정보 → 개인정보 동의 → 이전 이동 시 입력한 이름이 유지된다.
- Escape/닫기로 신청창이 닫힌다. 단, 초점 복귀 문제는 아래와 같다.

## 운영에서 재현한 문제

### 1. 검색어 입력 후 결과 개수와 모집상태가 잘못 표시됨 — 우선 수정

초기 결과 5개에서 검색어에 '감각통합'을 입력하면 실제 카드는 1개가 되지만 resultSummary와 a11yLive 모두 '검색 결과 5개 프로그램 · 1/1 페이지'가 유지된다. 해당 카드의 기존 '모집예정 / 신청 0명 · 제한 없음' 표시도 '0/0명 / 정원 마감'으로 바뀌며 기관·문의 등의 정보가 사라진다. '접근성점검결과없음'을 입력해 실제 결과가 없어져도 개수 안내는 5개다. 초기화하면 정상 카드로 복귀한다.

화면낭독기 사용자는 결과 개수와 모집상태를 잘못 안내받는다. 소스에는 app.js의 기본 renderPrograms와 enhancements.js의 확장 renderPrograms가 함께 있다. 검색 이벤트가 동일한 최종 렌더러를 사용하도록 통일하고, 결과·페이지·음성 안내를 같은 계산에서 갱신해야 한다. 수정 후 검색 0개·1개·복수 결과 및 필터 조합을 재검증한다.

### 2. 신청 단계 이동 후 초점이 BODY로 떨어짐 — 우선 수정

신청정보를 채우고 '다음: 개인정보 동의'를 누르면 화면은 동의 단계로 바뀌지만 document.activeElement는 BODY다. '이전'으로 돌아와도 BODY다. 현재 단계의 제목이나 첫 입력으로 초점을 옮기고 단계 변경을 알리는 처리가 필요하다.

### 3. 동의 선택지에 질문명이 연결되지 않음 — 우선 수정

운영 동의 화면의 라디오 이름은 '동의함', '동의하지 않음'만 반복된다. 세 동의항목의 라디오에 질문 제목과 연결된 fieldset/legend 또는 이름 있는 radiogroup이 없다. 폼 컨트롤만 이동하는 사용자는 어느 동의항목인지 놓칠 수 있다. 동의항목별 그룹 이름과 세부 행 이름을 연결해야 한다.

### 4. 신청창 닫은 뒤 원래 신청 버튼으로 초점이 돌아오지 않음

Escape 또는 닫기 후 초점이 mainContent 또는 BODY에 놓이는 것을 확인했다. 닫기 뒤 원래 프로그램의 신청 버튼으로 복귀해야 한다. accessibility.js에는 opener 저장 처리가 있지만 실제 흐름에서 복귀가 보장되지 않는다. 카드 재렌더링으로 버튼이 교체되는 경우도 고려하여 프로그램 식별자로 새 버튼을 찾아 복귀하도록 검토한다.

## 소스 검토에서 발견한 추가 확인 사항

- survey-form.mjs의 단답·장문·선택형·날짜 컨트롤에는 개별 label/aria-labelledby가 없다. 바깥 fieldset의 legend는 그룹명이며 개별 컨트롤의 명시적 이름 연결을 대신한다고 가정하면 안 된다. 질문 제목 ID를 컨트롤에 연결하는 것이 필요하다. 이 항목은 운영 설문 실행 결과가 아닌 소스 검토 결과다.
- 설문은 페이지별 fieldset/legend, 진행상태 role=status, 페이지 변경 시 focus 처리가 있다. 실제 설문이 연결된 신청 흐름과 각 질문 유형의 음성 출력·오류 복귀는 별도 검증이 필요하다. 이번 운영 모집중 프로그램은 파일 첨부형이었다.
- 검색 결과 요약과 별도 live 영역이 모두 aria-live=polite여서 중복 안내 가능성이 있다. 실제 화면낭독기로 중복 발화를 확인하고 안내 경로를 조정한다.
- 운영 로고는 접근성 트리에 '인천광역시 공식 심볼'로 노출됐다. 이전 v95 아이콘 배포 보고와 현재 화면이 달라 별도 배포 상태 확인이 필요하다.

## 후속 검증 기준

위 문제 수정 후 NVDA 또는 센스리더와 실제 이용 브라우저에서 검색 → 결과 이동 → 신청 → 오류 수정 → 동의 → 설문 → 이전 이동을 음성으로 확인한다. 테스트용 프로그램에서만 최종 제출·완료 안내를 검증한다. 관리자 화면, 외부 HWP/PDF/Google Form, 모바일 VoiceOver/TalkBack은 이번 점검 범위에 포함되지 않았다.
